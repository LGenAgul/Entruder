# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in Entruder itself (e.g. unsafe handling of session files, credential leakage, dependency with a known CVE), please **do not open a public GitHub issue**.

Instead, report it privately via GitHub's [private vulnerability reporting](https://github.com/LGenAgul/Entruder/security/advisories/new) feature, or reach out directly through [LinkedIn](https://www.linkedin.com/in/mate-agulashvili-968248183/).

Please include:
- A description of the vulnerability and its potential impact
- Steps to reproduce
- Any suggested fix if you have one

I aim to acknowledge reports within 72 hours and will work on a fix as quickly as possible.

## Scope

This policy covers the Entruder codebase only. Techniques and attack primitives that Entruder implements are documented publicly by Microsoft and the security research community, reports about those are out of scope.

## Intended Use

Entruder is designed for **authorized security testing and educational purposes only**. Use against tenants you do not own or have explicit written permission to test is outside the intended scope of this project and is the sole responsibility of the person conducting such activity.
